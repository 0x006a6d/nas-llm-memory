# NASホスト(NAS_USER)のcrontab — 復元用マスター(手順書§7)
# NAS_USER は deploy_nas_batch.sh が配置時に実行ユーザーへ展開するプレースホルダー
# UGOSアップデートでcrontabが消えた場合: crontab /volume2/claude-system/batch/crontab.txt
# (deploy_nas_batch.sh がリポジトリの nas/batch/ からこの場所へ配置する)
# 注意: UGOSの自動メンテナンス(SMART検査等)の時間帯と重ねないこと
#
# 時刻設計: バッチは .nightly.lock を非ブロッキングflockで取り合うため、
# 別時刻に置いても所要時間が振れると即FAILEDで欠測する(backfill実測83〜132分)。
# claudeを呼ぶバッチは1エントリ内で「;」直列にして競合を構造的に排除する
# (前段が失敗しても後段は走る)。nightly(実測12〜28分)には1時間の余裕を見る。

# 夜間統合バッチ(設計書§6) 03:00開始
0 3 * * *  /volume2/claude-system/batch/nightly.sh >> /volume2/claude-system/batch/nightly.log 2>&1

# 04:00 直列チェーン: backfill → edges → skill_scout
# - backfill は初回移行期間のみ(追補設計書§2)。全プロジェクトが「backfill完了」になったら
#   nightly.sh の節だけ削除する(edges 以降のチェーンは残す)
# - edges: 補足関係(fact_edges)の付与。未判定ペアが無ければ即終了
# - skill_scout: スキル候補の発掘。候補はskills-candidates/へ(skills/本体には触れない)
0 4 * * *  /volume2/claude-system/batch/nightly.sh --backfill-distill 2 >> /volume2/claude-system/batch/backfill.log 2>&1 ; /volume2/claude-system/batch/run_batch.sh edges_backfill --yes >> /volume2/claude-system/batch/edges.log 2>&1 ; /volume2/claude-system/batch/run_batch.sh skill_scout >> /volume2/claude-system/batch/skill_scout.log 2>&1

# DBバックアップ(日次04:30。flock非使用なのでチェーンと併走してよい)
30 4 * * *  /volume2/claude-system/batch/backup.sh

# 類似factの統合(ORGANIZE二段照合化 追補§4)。週次・日曜07:30(直列チェーンの最悪終了後)
30 7 * * 0  /volume2/claude-system/batch/run_batch.sh compact --yes >> /volume2/claude-system/batch/compact.log 2>&1

# sender(NAS自身も端末として送信 — 設計書§8)
17 * * * *  python3 /volume1/homes/NAS_USER/claude-config/hooks/sender.py
